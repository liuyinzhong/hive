# 抄送节点抄送类型支持「流程发起人」与「发起人直属上级」

> 方案日期：2026-09-23。跨前后端需求：主改动在 hive（流程设计器），配套改动在 hive-admin-go（发布校验与宽松语义）。工单 01 在 hive-admin-go 执行，工单 02 在 hive 执行。

## Problem Statement

流程设计器的抄送节点目前抄送类型仅支持「指定用户、指定角色、审批参与人」三种，无法配置"把流程经过该节点的知会发给流程发起人本人（或其直属上级）"。常见的"发起人自留档知会""上级知会"场景只能通过指定用户硬编码，发起人变化时需要改流程图。

## Solution

抄送类型扩展为五值：指定用户、指定角色、审批参与人、**流程发起人**、**发起人直属上级**。后两类与审批参与人一样不选择具体人员，由引擎在运行期按流程上下文解析。同时补齐发布期枚举白名单校验，并修复抄送节点在"发起人未配置直属上级"时会报错阻塞流程的宽松语义缺陷。

## User Stories

1. 作为流程设计者，我想在抄送节点选择「流程发起人」，让流程经过该节点时自动向发起人本人发送抄送知会，而不必在每个流程里硬编码发起人账号。
2. 作为流程设计者，我想在抄送节点选择「发起人直属上级」，让发起人的上级在流程经过该节点时收到知会。
3. 作为流程设计者，选择「流程发起人」「发起人直属上级」「审批参与人」这类运行期解析的类型时，属性面板不应出现人员/角色选择框，只显示解释文案。
4. 作为流程设计者，切换抄送类型时，上一类型选中的用户/角色应被清空，画布不残留脏数据。
5. 作为流程使用者，即使发起人未配置直属上级，流程经过「发起人直属上级」抄送节点时也应继续流转（该节点抄送为空），而不是报错卡死。
6. 作为流程管理员，我想在保存/发布包含非法抄送类型或审批办理人来源的定义时得到明确错误，而不是等到流程运行到该节点才失败。
7. 作为国际用户，新增的抄送类型选项与提示文案需要有中英文词条。
8. 作为存量流程的使用者，已发布定义与运行中实例按自身快照执行，不受本次枚举扩展影响。

## Implementation Decisions

- **枚举扩展**：抄送类型取值扩为 `user / role / participant / starter / leader`。后端运行时人员解析已支持 `starter` 与 `leader`，引擎无需改动。
- **免选人语义**：`participant / starter / leader` 三类在设计期不配置人员，提交时人员 ID 数组置空，画布不保存人员名称快照；`user / role` 维持现状必须选择。
- **后端发布/保存校验**：图结构校验（保存草稿与发布共用）新增枚举白名单——审批节点办理人来源限 `user / role / leader / starter`，抄送节点抄送类型限五值；非法值在校验阶段报明确错误。与既有"审批节点未配置审批人"校验同层同风格。
- **leader 宽松语义修复**：抄送节点（宽松模式）解析「发起人直属上级」时，发起人未配置直属上级或解析不到发起人则返回空列表、不报错、流程继续；审批节点保持现状报错阻塞。
- **提示文案**：新增抄送场景专用国际化词条（"运行时抄送给流程发起人本人"“运行时抄送给发起人的直属上级，未配置时抄送为空"），中英文同步；选项文案复用既有「流程发起人」「发起人直属上级」词条。
- **文档同步**（同一次交付完成）：
  - 后端流程定义规则：修正 WF-DEF-012（补"流程发起人"，与代码恢复一致），新增抄送类型五值规则条目（含宽松解析语义）。
  - 后端领域词汇：已沉淀「抄送类型」「办理人来源」词条（本次已完成）。
  - 前端设计器 UI 文档：补抄送节点类型选项与交互说明。
  - CONTEXT-MAP 跨域关系：核对后无跨域变化。
- **兼容性**：
  - 无数据库结构变更，无迁移 SQL 与回滚脚本需求。
  - 画布 JSON 新增枚举取值属于向后兼容扩展：存量定义只含旧值，语义不变；已发布/运行中实例按快照执行不受影响。
  - 白名单为超集校验，先于前端上线也不影响存量草稿保存。
- **无需 ADR**：各项决策均可逆、无实质架构权衡（按 ADR 三条件评估跳过）。

## Testing Decisions

- 前端（hive）：对改动文件执行局部类型检查（typecheck，按文件过滤存量错误）；不新增单测（项目当前阶段约定）。
- 后端（hive-admin-go）：`go build ./...`、`go vet ./...`、`go test ./...` 作为编译与存量测试验证；不新增 `_test.go`。
- 手工验证路径：设计器为抄送节点分别配置五种类型并保存、发布；发起实例观察抄送通知与流程流转（重点：发起人未配置直属上级时不阻塞）。

## Out of Scope

- 抄送节点发布期的接收人可解析性预校验（维持现状：仅审批节点做发布前可解析校验，抄送宽松语义下运行期为空不阻塞）。
- 审批侧办理人来源的其它新增类型（如多级上级、部门主管）。
- 已发布定义的自动重发布或画布数据迁移。
- API 层抄送类型的独立 TypeScript 类型（画布以 JSON 字符串整体传输，前后端无独立 DTO 字段）。
