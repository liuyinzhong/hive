# 表单 Schema UI 规则

## 列表与基础资料

- 列表支持查询、新增、编辑、进入设计器、状态切换和删除，并按对应 form:schema 权限控制入口。

- 基础弹窗维护名称、分类、布局、状态和备注；Schema 标识由后端通过公共编码流水自动生成，不在弹窗中输入，列表和详情只读回显。

- 编辑提交前按后端退草稿口径（字段结构、布局或状态变化）检测本次修改；命中且表单被工作流引用时，先弹二次确认列出将被退回草稿的流程名称与当前状态，确认后才提交，取消则留在弹窗继续编辑。

- 删除前二次确认；若仍被工作流定义引用，保留列表行并展示后端冲突。

## 设计器

- 设计器通过拖放或节点操作维护字段树，属性面板编辑字段名、组件配置和校验规则。

- 设计态画布内所有组件只读、不触发交互（点击只用于选中字段，拖拽用于排序）；组件的交互能力只在预览态和工作流运行表单中开放。输入类组件走原生只读，其余组件由控件层样式统一屏蔽交互，外观保持正常不置灰。

- 字段名在整份 Schema 中统一检查，父子层级不能重复；前端提示不能替代后端整树校验。字段标识不允许清空：清空时不修改当前设计，输入框失焦后回填原值；改为与其它字段重名时前端提示并拒绝。属性编辑产生暂不合法的中间态（如字段名输入到一半）时，画布保留上一次有效渲染，不清空。

- 支持单列、双列和三列布局，保存提交完整 Schema 结构。

- 新拖入画布的组件默认携带 `controlClass: "w-full"`（控件占满所在列宽），仅在新增字段时写入，存量字段不回填。

- 上传组件默认走项目统一登录态上传接口（`/system/upload`），上传实现由前端表单适配器（Upload 组件包装层）统一注入，设计器预览和工作流运行表单均可直接上传；已配置 action 或 customRequest 时优先使用显式配置。

- 高级 JSON 编辑是同一份结构的另一种编辑入口，不允许执行自定义脚本；解析失败或结构不合法时不能覆盖当前有效设计，应用前对替换后的整份 Schema 编译校验，失败时提示原因并保持原设计不变。

- 预览只运行当前设计器状态，用于检查布局和校验交互，不代表工作流已经发布。

- 保存前按后端退草稿口径（字段结构、布局或状态变化）检测本次修改；命中且表单被工作流引用时，先弹二次确认列出将被退回草稿的流程名称与当前状态，确认后才提交。保存成功后刷新保存基线，避免连续保存时重复误判。
