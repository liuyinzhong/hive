# 登录与访问控制 UI 规则

## 登录和个人资料

- 登录页通过 auth API 建立会话，认证失败保留用户名等非敏感输入并展示稳定错误；不得记录或回显密码、Token。
- 登录页滑块已服务端校验且默认隐藏：正常登录只有用户名和密码；该用户名失败达到阈值后（后端 SYS-ACL-046），登录接口返回 HTTP 428，页面据此展示滑块并从 `POST /public/captcha` 领取一次性挑战票据，票据随登录请求提交。触发后的每次登录失败都重置滑块并重领票据；票据有效期 5 分钟，过期后重试即可。
- 登录后从 profile、menus 和 codes 获取用户资料、动态路由和原子权限；页面不能从角色名称猜测授权。
- 注册、验证码登录、二维码登录和找回密码页面目前是 Vben 占位界面，提交函数没有连接业务 API；不得描述为可用认证方式或仅凭这些页面补前端逻辑。
- 个人资料基本设置页读取当前 profile 回显；头像和邮箱可编辑保存（`PUT /auth/profile`），头像复用系统上传组件支持 1:1 裁剪，保存成功后用返回的最新资料刷新 `useUserStore`，左侧头像即时更新。真实姓名、登录名和手机号为只读，仍由用户管理维护。
- 个人中心“我的签名”页签上传单张签名图片（png/jpg/jpeg、≤2MB、不裁剪），进入页面读取当前 profile 回显，保存走 `PUT /auth/profile` 的 `signature` 字段；移除已传图片后保存即清空签名。签名仅作为个人资料存储，页面本身不校验图片内容。
- 修改密码页（个人中心）走真实接口 `PUT /auth/password`：旧密码必填，新密码与确认密码使用统一强度规则（8～72 位且至少两类字符，见 `#/utils/password`，与后端一致），新密码带强度条展示；修改成功提示后本地清理会话返回登录页，其它在线页签由 `forceLogout` 实时事件静默登出。安全设置和通知设置仍是硬编码演示内容，不是已实现功能。
- 密码变更后的强制退出体验为静默跳转登录页，不弹窗提示；旧凭证失效由后端密码版本号比对保证（后端 [登录与访问控制规则](../../../hive-admin-go/business-docs/system/access-control.md) SYS-ACL-040～045）。
- 要启用上述能力，必须先明确业务规则、认证安全方案和后端接口，再同步前端实现、文档与权限，不能继续沿用演示成功状态。

## 用户管理

- 用户列表支持筛选、新增、编辑、详情、重置密码、状态和删除；系统内置用户不应出现在普通管理范围。
- 列表“角色”单元格对持有 `system:user:permission` 权限码的用户渲染为链接（复用 CellLink 渲染器），点击打开只读抽屉查看该用户全部角色关联的权限明细；无该权限码时保持静态文本。抽屉表格以分组为树形父行（默认收起，角色组展示角色名、状态、数据范围和授权节点数量；个人权限组在角色组之前，展示“额外授权”与“禁止”两段，禁止组标红并标注“合并优先”），展开后按菜单树层级嵌套展示授权明细（目录→页面→按钮，层级由树缩进表达，目录保留其下被授权的后代），明细列展示名称、菜单类型、路由路径、原子权限码和菜单状态；顶部搜索框按分组名或权限名称/路径/类型/权限码实时过滤，命中节点及其祖先链保留并自动展开；明细为角色当前配置事实，停用角色与停用菜单照常展示并标注状态，同一权限被多个角色授予时在各分组内分别出现，不去重；未关联角色且无个人权限的用户显示空态（后端 [SYS-ACL-018](../../../hive-admin-go/business-docs/system/access-control.md)）。
- 操作列“个人权限”入口使用 `system:user:personalPermission` 权限码控制展示，打开双 tab 抽屉维护该用户的个人权限：『额外授权』与『禁止』两棵菜单权限树（复用角色表单权限树的树数据与三列按钮布局），各自勾选集合整体提交、完整替换保存；抽屉顶部固定提示“个人权限只影响菜单和按钮授权，不改变数据范围；生效权限 = 角色授权 ∪ 额外授权 − 禁止”；同一菜单不允许同时出现在两棵树中，后端校验为准（后端 [SYS-ACL-019](../../../hive-admin-go/business-docs/system/access-control.md)）。
- 重置密码操作使用 `system:user:resetPassword` 权限码控制展示，弹窗表单输入新密码与确认密码（强度规则与修改密码一致），提交走 `PUT /system/users/{userId}/password`；成功后目标用户全部会话失效，列表保留不动。
- 表单从有效角色、部门和用户选项加载关联数据。角色与部门多选按完整集合提交。
- 直属领导不能选择自己；编辑切换用户时清除上一个用户的旧表单状态。
- 状态切换、删除或保存成功后刷新当前页；后端保护当前用户和内置用户时，页面保留记录并展示原因。

## 角色和部门

- 角色表单维护名称、状态、数据范围及菜单/按钮权限树；提交的是完整授权集合。数据范围交互见 [数据权限 UI 规则](./data-permission-ui.md)。
- 角色列表提供「用户」操作，抽屉内以分页表格维护角色用户；查询使用 `system:role:detail` 权限码，添加/移除使用 `system:role:user` 权限码，且写操作与角色其它写操作一样要求操作者拥有全部数据范围。
- 添加用户复用用户管理分页列表接口选择，前端排除已是角色用户的记录；添加与移除均为增量提交，不做全量集合提交，重复操作由后端幂等跳过。角色用户与用户表单中的角色多选是同一份授权关系的两个入口。
- 选择“自定义部门”时显示部门树并至少选择一个部门；选择其它范围时清空自定义部门集合。新建角色默认“仅本人”，列表展示当前范围。
- 角色创建、修改、启停和删除还要求后端判定操作者拥有全部数据范围；仅隐藏按钮不能替代该校验。
- 部门以树表展示，新增子部门时预填父节点；编辑父节点时排除自身和后代。
- 有子部门或关联用户时删除会失败，页面不能乐观移除。

## 菜单和按钮权限

- 菜单管理按目录、页面、内嵌页、链接和按钮类型动态展示适用字段。
- 菜单列表操作列提供「受众」入口（`system:menu:detail` 权限码），打开三 tab 只读抽屉：『受众角色』全量展示收录该菜单的角色（名称、状态、数据范围、备注、收录时间，含停用角色）；『额外授权用户』与『被禁止用户』分页展示被直接授予或禁止该菜单的普通用户（登录名、姓名、状态、部门、写入时间），支持关键字和状态筛选（后端 [SYS-ACL-028](../../../hive-admin-go/business-docs/system/access-control.md)）。
- 徽标类型不是“文字”时，徽标内容输入框禁用并自动清空已填内容；编辑带残留徽标内容的历史数据时同样清空，提交后不再保留。
- 按钮节点不参与路由，名称为空，标题使用国际化 key，authCode 使用原子权限码。
- 页面名称、路径和权限码的唯一性提示只用于交互，最终以后端校验为准。
- 删除父菜单前必须先处理子菜单；成功后重新加载整棵菜单树和权限相关数据。
