# 数据权限 UI 规则

角色数据范围的后端语义、归属字段和全接口分类以 [后端数据权限规则](../../../hive-admin-go/business-docs/system/data-permission.md) 为准。前端只负责配置和呈现，不是安全边界。

## 角色配置

- 角色列表展示后端返回的数据范围名称，不能从角色标题推断范围。
- 角色表单提供：全部数据、自定义部门、本部门、本部门及下级、仅本人、无数据。
- 选择“自定义部门”时显示部门树并要求至少选择一个启用部门；切换为其它范围时提交空的 `dataScopeDeptIds`，避免保留失效配置。
- 新建角色默认“仅本人”；编辑使用详情返回的 `dataScope` 和 `dataScopeDeptIds` 回填。
- 角色创建、修改、启停和删除除原子按钮权限外还要求当前操作者拥有全部数据范围。后端返回 403 时页面保留现有数据并展示错误，不能用隐藏字段或重试绕过。

## 业务页面

- 用户、文件、日志、研发工作项、研发统计、ERP 单据/库存、患者、挂号和实际排班页面直接消费后端已过滤结果，不向 API 追加自定义 `dataScope`、创建人或部门集合来决定授权。
- “全部用户”、版本、需求、库存余额、患者、排班等下拉选项也可能被后端收窄。空选项应按正常空态处理，不能回退请求一个未受限接口或缓存旧用户的结果。
- 列表中曾可见的记录在调岗或角色收紧后可能从刷新结果消失；详情和写动作仍可能返回不存在/无权访问。页面应重新查询并展示稳定错误，不能仅凭本地行缓存继续提交。
- 批量动作任一 ID 越界时后端整批失败，前端不得把失败当成部分成功并乐观删除可见行。
- 任务和库存导出按 Worker 执行时的当前权限生成。任务因用户失效或授权变化失败时，下载中心展示后端失败原因，不使用创建任务时的列表数据在浏览器补生成文件。

## 不受通用角色范围扩大的页面

- 流程实例、待办和抄送按发起人、办理人和接收人；医生工作台、病历和处方按当前医生/接诊关系；处方审核按审核规则。角色范围为“全部”也不能在前端显示绕过领域归属的入口。
- 基础资料、产品档案、仓储结构、医疗基础档案、表单 Schema、流程定义和打印模板是全局主数据，仍由原子按钮权限控制；前端不能因角色范围为“无数据”擅自隐藏已授权的全局配置页面。

## 文件提示

文件元数据列表受数据范围限制，但现有 `/uploads/**` 是公开静态 URL。页面不得把“文件列表看不到”描述成文件内容已经私有；敏感文件需求必须先配合后端建设私有下载接口。
