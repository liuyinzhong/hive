# 菜单消息推送 UI 规则

## 当前呈现边界

当前菜单消息只呈现为动态菜单数字角标：叶子页面显示自身未读数量，目录显示子孙未读总数，按实际数值显示，不进行 `99+` 截断。

未读角标颜色优先继承菜单管理中该菜单配置的徽标颜色（`badgeVariants`，目录同样适用）；未配置时默认红色（`destructive`）。角标内容与类型仍由未读数动态覆盖为数字角标，归零后恢复菜单原有角标配置。

布局右上角的铃铛是应用层自研的通知中心组件（`src/layouts/components/notification-center.vue`），通过 BasicLayout 的 notification 插槽挂载，逐条消费菜单消息：列表为当前用户全部来源、含已读、最近 100 条、按创建时间倒序，在弹层打开时拉取，打开期间不实时刷新。铃铛红点在未读总数大于 0 时亮起，具体计数语义仍由菜单角标承担。通知中心只读改消息状态、不删除消息；消息项不使用头像字段，以来源菜单名标识归属。

## 启动与停止

- 业务布局挂载后启动消息 Store，先请求完整未读汇总，再建立 SSE。
- Store 已运行时重复启动不创建第二条连接。
- 布局卸载或用户状态重置时中止连接、清空汇总和下载任务修订号，并恢复菜单原有角标。
- SSE 异常后重新获取完整汇总，等待 2 秒再连接；首次请求失败不阻塞菜单渲染。

## 事件消费

事件名作为后端业务规则正文，登记在后端 `business-docs/system/message-push.md` 的 “SSE 事件名” 章节；前端代码不得使用裸字符串字面量，统一通过 `SystemMenuMessageApi.EventName` 常量引用（见 `apps/web-antdv-next/src/api/system/message.ts`）。

| 事件名 | 常量 | 推送时机 | 前端处理 |
|---|---|---|---|
| `unreadSummary` | `EventName.UnreadSummary` | 建立连接后立即推送一次；之后未读汇总发生变化时推送 | 以服务端完整数组覆盖本地汇总并重新计算全部菜单角标 |
| `downloadTaskChanged` | `EventName.DownloadTaskChanged` | 下载任务终态生成或状态变化时推送 | 仅递增下载任务修订号，由下载中心监听后重新查询列表 |

- 格式错误的事件不写入状态，等待后续完整汇总校准。
- 服务端每 30 秒发送一次心跳，心跳事件不携带业务数据，前端不写入状态。

## 消息提示音

收到 `unreadSummary` 事件且未读总数相对本地当前汇总增加时播放提示音；用户已读、校准、总数不变或减少的推送不触发。每次 SSE 连接的首个 `unreadSummary` 视为初始化全量推送，也不触发。提示音能力受用户偏好开关 `enableNewUnreadSummary` 控制，开关位于偏好设置面板”消息提醒”分组。

- 提示音文件：`apps/web-antdv-next/public/sounds/sound.mp3`，通过 `/sounds/sound.mp3` 静态访问，时长约 2 秒。
- 触发条件：每次建立 SSE 连接（包括应用启动首次与重连）后收到的首个 `unreadSummary` 不触发；之后的 `unreadSummary` 事件，未读总数相对本地当前汇总增加才触发。与本地汇总对比而不是与上一次服务端推送对比，是因为已读成功后本地汇总先行减少，服务端推送只做最终校准；用户点击未读菜单触发的校准推送总数不变或减少，不响铃。
- 并发处理：使用单例 `HTMLAudioElement`，新事件到来时重置 `currentTime` 为 0 从头播放，打断前一次未播完的音频。
- 偏好关闭：偏好开关 `enableNewUnreadSummary` 为 `false` 时不播放。
- 自动播放限制：浏览器自动播放策略阻止（用户未与页面交互过）时 `play()` 被 reject，静默处理不报错。
- `downloadTaskChanged` 事件不触发提示音。
- Store 停止时暂停并重置正在播放的音频，避免登出或重置后继续响铃。

实现见 `apps/web-antdv-next/src/store/menu-message.ts` 的 `playMessageSound`。

## 已读交互

- 用户选择菜单时，布局把路径交给消息 Store。
- 只有路径存在未读汇总、当前用户确实拥有该菜单且该菜单没有子菜单时才请求已读。
- 同一路径正在提交时忽略重复操作。
- 成功后立即从本地汇总移除，再由服务端推送进行最终校准；失败时保留现有角标。

## 通知中心交互

- 新未读到达（未读总数增加的 `unreadSummary` 推送，与提示音同一触发时机）时，顶栏铃铛播放一次摇铃动画；动画是视觉信号，不受提示音偏好开关控制，动画进行中的再次到达合并为一次。
- 点击消息项：先按整组已读口径处理归属菜单（复用菜单已读接口与 Store 的 `markMenuRead`），再跳转到该菜单路径并关闭弹层；与"进入菜单必整组已读"的既有不变量一致，跳转后该菜单其它未读角标随之清零。
- 消息项上的"标为已读"：仅把这一条置为已读（逐条已读），不跳转、不影响同菜单其它消息的角标；这是前端唯一的单条已读入口。
- 头部"全部已读"：仅存在未读时显示；点击后全量已读，本地立即清空汇总与全部角标，由服务端推送最终校准。
- 来源菜单已删除的消息没有跳转路径，点击无响应，只能通过按钮逐条已读。
- 时间展示取后端返回时间（`2006-01-02 15:04:05`）的"月-日 时:分"片段；文案使用 `system.notice.*` 国际化 key，中英文同步维护。

## Demo 页面

- 用户支持多选，候选用户和后端提交都受当前角色数据范围约束；菜单树禁用目录和所有存在子页面的节点，只允许选择叶子页面。
- 每个用户的消息数量限制为 1 至 1000。
- 提交成功后清空表单；最终有效用户、菜单和权限以后端校验为准。
- 创建 Demo 消息接口需要 `system:messageDemo:create`，页面本身不应被视为生产消息编辑器。

## 已知限制

1. 通知中心只保留最近 100 条的瞬时列表，没有独立的消息归档页面；更早的消息只能通过菜单角标进入对应页面消费。
2. 下载进度没有独立轮询；若多实例部署导致 SSE 事件未到达，已打开的下载中心可能需要用户手工刷新。
3. 菜单角标会临时修改动态菜单对象，但 Store 保留原角标并在未读归零或停止时恢复。
