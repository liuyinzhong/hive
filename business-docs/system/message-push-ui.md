# 菜单消息推送 UI 规则

## 当前呈现边界

当前菜单消息只呈现为动态菜单数字角标：叶子页面显示自身未读数量，目录显示子孙未读总数，超过 99 显示 `99+`。

布局右上角的 `Notification` 组件仍使用 `basic.vue` 内的框架演示数组，清空、已读和点击行为均只修改本地演示数据，与后端菜单消息没有关系。开发时不要把两套状态合并理解。

## 启动与停止

- 业务布局挂载后启动消息 Store，先请求完整未读汇总，再建立 SSE。
- Store 已运行时重复启动不创建第二条连接。
- 布局卸载或用户状态重置时中止连接、清空汇总和下载任务修订号，并恢复菜单原有角标。
- SSE 异常后重新获取完整汇总，等待 2 秒再连接；首次请求失败不阻塞菜单渲染。

## 事件消费

- `unreadSummary`：以服务端完整数组覆盖本地汇总并重新计算全部菜单角标。
- `downloadTaskChanged`：只递增下载任务修订号，由下载中心监听后重新查询列表。
- 格式错误的事件不写入状态，等待后续完整汇总校准。

## 已读交互

- 用户选择菜单时，布局把路径交给消息 Store。
- 只有路径存在未读汇总、当前用户确实拥有该菜单且该菜单没有子菜单时才请求已读。
- 同一路径正在提交时忽略重复操作。
- 成功后立即从本地汇总移除，再由服务端推送进行最终校准；失败时保留现有角标。

## Demo 页面

- 用户支持多选，候选用户和后端提交都受当前角色数据范围约束；菜单树禁用目录和所有存在子页面的节点，只允许选择叶子页面。
- 每个用户的消息数量限制为 1 至 1000。
- 提交成功后清空表单；最终有效用户、菜单和权限以后端校验为准。
- 创建 Demo 消息接口需要 `system:messageDemo:create`，页面本身不应被视为生产消息编辑器。

## 已知限制

1. 前端没有逐条菜单消息列表，因此不能展示已持久化的标题、内容和创建时间。
2. 下载进度没有独立轮询；若多实例部署导致 SSE 事件未到达，已打开的下载中心可能需要用户手工刷新。
3. 菜单角标会临时修改动态菜单对象，但 Store 保留原角标并在未读归零或停止时恢复。
